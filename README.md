# Poker project — локальная разработка

## Браузерное демо

Из корня выполните `pnpm.cmd install`, затем `pnpm.cmd dev`.
Откройте адрес, показанный Vite (обычно http://127.0.0.1:5173/).
Остановка — Ctrl+C в терминале.

Если сервер не запущен, доступен только учебный просмотр стола.
`pnpm.cmd build` собирает движок, сервер и frontend.

## Локальный real-time сервер

В одном окне PowerShell перейдите в папку проекта и выполните
`pnpm.cmd install`, затем `pnpm.cmd dev:all`. Откройте
`http://127.0.0.1:5173/`. Для остановки нажмите Ctrl+C. Если старые окна
с сайтом или сервером уже запущены, сначала остановите их: порты 5173 и
3001 должны быть свободны.

Также можно запустить два окна: `pnpm.cmd dev:server` в первом и
`pnpm.cmd dev` во втором. Создайте
комнату и введите её код во втором браузере. Две вкладки одного профиля
используют один гостевой аккаунт; для двух игроков используйте другой
браузер или окно инкогнито.

В настройках доступны русский и английский языки, отключение звуков и
громкость. Выбор сохраняется в локальных данных браузера.
В меню «Друзья» можно поделиться своим кодом, отправить заявку по коду,
принять входящую заявку, увидеть статус друга и удалить его из списка.
Из комнаты можно пригласить друга, который находится в сети; он выбирает,
принять приглашение или отказаться.
Это локальная версия: для друзей с других компьютеров необходим сервер,
доступный через интернет.

Гостевая сессия, фишки и текущая раздача хранятся локально в SQLite.
Файлы `apps/server/data/poker.sqlite` и `apps/server/data/snapshot.key`
нужно сохранять вместе: ключ нужен для восстановления раздач. Папку можно
изменить через `POKER_DATA_DIR`. При очистке данных браузера доступ к
гостевому аккаунту будет потерян. Для игры через интернет требуется
отдельное размещение и HTTPS: локальный адрес виден только на этом компьютере.

## Игра в одной домашней сети

Оба устройства должны быть подключены к одной доверенной сети. Узнайте IPv4
адрес компьютера через `ipconfig` (например, `192.168.1.10`). В первом
окне PowerShell в папке проекта задайте адрес сайта и запустите сервер:

```powershell
$env:POKER_ORIGIN="http://192.168.1.10:5173"
pnpm.cmd dev:server
```

Во втором окне из той же папки запустите интерфейс:

```powershell
pnpm.cmd --filter @poker/web dev:lan
```

Вместо примера укажите свой IPv4 адрес. На обоих устройствах откройте
`http://192.168.1.10:5173` с вашим адресом. Брандмауэр Windows может
запросить доступ для Node.js в частной сети. Этот режим разработки
предназначен только для доверенной локальной сети, не для интернета.
Для обычной работы через 127.0.0.1 закройте оба процесса и запустите
их в новых окнах без `POKER_ORIGIN`.

Для будущего размещения нужно направить `/api` и `/socket.io` через
HTTPS reverse proxy на сервер, а остальные запросы — на собранный
интерфейс. Укажите точный HTTPS origin в `POKER_ORIGIN`; cookie получит
атрибут Secure. `POKER_HOST` и `PORT` настраивают адрес и порт сервера,
по умолчанию он слушает только 127.0.0.1:3001. Это настройки, а не готовое
публичное размещение.

## Подготовка размещения через Docker

В проект добавлены Dockerfile, Compose и Caddy: Caddy принимает HTTPS,
сервер отдаёт собранный сайт и WebSocket, данные хранятся в томе
`poker_data`. Нужны сервер с Docker Compose, домен, указывающий на него,
и доступные извне порты 80 и 443. Скопируйте `.env.example` в `.env`,
укажите `POKER_DOMAIN` без `https://`; поля Google можно оставить пустыми.
На сервере из папки проекта выполните `docker compose up -d --build`.
Это конфигурация для одного сервера, а не отказоустойчивая инфраструктура.
Docker на компьютере разработки отсутствует, поэтому сборка контейнера и
получение сертификата ещё не проверены в реальном окружении.

Регулярно делайте резервные копии содержимого тома `poker_data` вместе с
`snapshot.key`; для согласованности останавливайте приложение на время
копирования SQLite. Не удаляйте том при переустановке: в нём кошельки и
текущие раздачи. Секреты из `.env` нельзя публиковать.

## Вход через Google

Кнопка входа появляется, когда серверу заданы `GOOGLE_CLIENT_ID` и
`GOOGLE_CLIENT_SECRET`. Создайте OAuth-клиент типа Web application в
Google Cloud и добавьте точный redirect URI: значение `POKER_ORIGIN` плюс
`/api/auth/google/callback`. Например, для публичного сайта
`https://example.com/api/auth/google/callback`. Затем задайте переменные
в окне запуска сервера:

```powershell
$env:GOOGLE_CLIENT_ID="ваш-client-id"
$env:GOOGLE_CLIENT_SECRET="ваш-client-secret"
pnpm.cmd dev:server
```

Не публикуйте и не передавайте секрет клиенту. Для интернета требуется
HTTPS и правильно настроенный публичный адрес. При первом входе нового
Google-аккаунта текущий гостевой кошелёк привязывается к нему. Если
Google-аккаунт уже использовался, открывается его кошелёк; балансы не
объединяются. В этом случае вернуться к гостевому кошельку можно кнопкой
«Вернуться в гостевой профиль» в том же браузере. Если гость был привязан
к новому Google-аккаунту, эта кнопка создаст новый гостевой профиль.
При очистке данных браузера доступ к непривязанному гостю теряется.
Перед сменой аккаунта выйдите из игровой комнаты. При
входе в другой новый Google-аккаунт создаётся отдельный кошелёк.
Без OAuth-реквизитов по-прежнему доступен гостевой режим. Настройка и
проверка реального входа требуют Google Cloud проекта владельца сайта.

## Проверки

Нужны Node.js 22+ и pnpm 12.18.0 (указан в packageManager).

```powershell
cd C:\Users\User\Desktop\poker-project
pnpm.cmd install --frozen-lockfile
pnpm.cmd test
pnpm.cmd typecheck
pnpm.cmd build
```

`pnpm test:watch` запускает тесты в режиме наблюдения.
`pnpm clean` удаляет результаты TypeScript-сборки.
Проверка типов охватывает исходники, тесты и конфигурацию Vitest.

## Файлы

- `packages/game-engine/src/cards.ts` — Card, Rank, Suit, константы и форматирование.
- `packages/game-engine/src/deck.ts` — создание колоды и Fisher–Yates.
- `packages/game-engine/src/evaluator.ts` — оценка пяти/семи карт и сравнение рук.
- `packages/game-engine/src/errors.ts` — ошибки с машинно-читаемыми кодами.
- `packages/game-engine/src/index.ts` — публичный API.
- `packages/game-engine/test` — проверка поведения.
- `apps/web` — интерфейс; `apps/server` — локальный сервер и кошелёк.
- `packages/config`, `packages/database`, `packages/protocol` — заготовки.

## Использование

Другой workspace-пакет должен добавить зависимость
`"@poker/game-engine": "workspace:*"`. После сборки:

```ts
import {
  createDeck, shuffleDeck, evaluateSeven, compareHandValues,
} from "@poker/game-engine";

const deck = shuffleDeck(createDeck());
const board = deck.slice(4, 9);
const first = evaluateSeven([...deck.slice(0, 2), ...board]);
const second = evaluateSeven([...deck.slice(2, 4), ...board]);
const comparison = compareHandValues(first, second); // -1, 0, 1
```

Пакет предназначен для Node.js: shuffle импортирует `node:crypto`.
Игровой сервер в будущем должен хранить колоду у себя и отправлять клиенту
только разрешённые карты. Сам пакет пока не реализует эту сетевую границу.

## Контракты

- Card: неизменяемые поля rank (2–14) и suit (clubs/diamonds/hearts/spades).
- createDeck возвращает новые массив и объекты; созданные карты заморожены.
- shuffleDeck возвращает новый массив, не изменяет исходный; ссылки на
  неизменяемые карты сохраняются. Пользовательский RNG предназначен для тестов.
- evaluateFive принимает ровно пять уникальных допустимых карт,
  evaluateSeven — ровно семь. Невалидные карты проверяются и в runtime.
- HandValue: category, tiebreak и пять выбранных cards.
- Категории возрастают от HighCard до StraightFlush. Royal flush — это
  StraightFlush со старшей картой 14, а не отдельная категория.
- Туз в A–2–3–4–5 имеет верхнее значение стрита 5.
- Сравнение учитывает категорию и все кикеры, но никогда масть.
- compareHandValues принимает значения, полученные от evaluator.
- Порядок входных карт не влияет на результат. При равных физических
  вариантах выбирается стабильный набор; cards отсортированы по рангу,
  а не по порядку образования комбинации.
- Ошибки: INVALID_CARD_COUNT, INVALID_CARD, DUPLICATE_CARD,
  INVALID_RANDOM_VALUE.

Онлайн-размещение и полноценная эксплуатационная инфраструктура ещё не
развёрнуты; Google-вход требует OAuth-реквизитов и проверки с реальным аккаунтом.
