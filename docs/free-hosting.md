# Бесплатное размещение: Render + Neon

Выбран вариант без банковской карты: бесплатный Web Service Render и
бесплатная PostgreSQL-база Neon. Не создавать платные ресурсы и не менять
тариф без отдельного согласия владельца.

Создан Neon-проект `poker-friends` в `aws-eu-central-1`. Для постоянного
запуска сервер использует `DATABASE_URL`, а локальная разработка без этой
переменной продолжает работать с SQLite. В PostgreSQL сохранены кошельки,
гостевые сессии, друзья, раздачи и их зашифрованные снимки. Активные комнаты
по-прежнему обслуживает один процесс WebSocket-сервера.

`POKER_SNAPSHOT_KEY` обязателен при `DATABASE_URL`: это случайные 32 байта
в стандартном Base64. Он должен быть постоянным секретом Render и никогда не
должен попадать в Git, чат или логи. Его смена во время незавершённой раздачи
не позволит расшифровать её снимок.

`render.yaml` создаёт только бесплатный сервис и не создаёт диск. Render
может усыплять бесплатный сервис после простоя: первый вход друзей после сна
может занять некоторое время. PostgreSQL Neon хранит данные вне временной
файловой системы Render.

Neon MCP сейчас не может выполнить SQL из-за неверно закреплённой роли
подключения (`Timur_Gutaew` отсутствует на ветке), поэтому исходная миграция
ещё не применена к облачной базе. Это безопасная остановка: основная база
остаётся пустой. После переподключения Neon применить
`apps/server/sql/postgres/001_initial.sql` к `neondb` прямым подключением,
проверить создание сессии и только затем добавить `DATABASE_URL` в Render.

Источники: https://render.com/docs/free, https://neon.com/docs/introduction/plans,
https://neon.com/docs/connect/connection-pooling.
